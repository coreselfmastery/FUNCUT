# Known issues and verified limitations

> Counts and the canonical feature inventory live in
> [docs/FEATURES.md](docs/FEATURES.md); this file carries the dated
> limitation detail, not the numbers.

This file records limitations that remain on `main`. It is not a list of historical bugs that have already been fixed.

## Remaining limitations

1. **Lottie/dotLottie playback is implemented on `main`.** PR #91 merged as `4a65a7b07b66d20d586d59c9da01cc05ab6624e9`: rasterlottie-backed `NodeKind::Lottie` playback, bounded v1/v2 dotLottie loading, image resolution and support diagnostics, with its full CI/Geneva/Nix matrix green on the exact merge head.

2. **Geneva sidecar is a pinned binary (v1.6.0, closed source).** Its limitations are documented in `docs/MOTION.md`: no path drawing, no variable-font axes, no in-keyframe weights, keyframes in px/% only, and markup animations static per bake. Keep the documented guards and warnings aligned with the actual sidecar behavior.

3. **Linux VAAPI encode is integrated; on-hardware validation remains.** PR #95 merged as `48cdcd898b97b930884bacddcbfcf8f877a02897`: the export sheet names the machine's own GPU (VAAPI) or the CPU by choice, the encoders carry the field, and `vaapi_possible` gates every VAAPI encoder name on the DRI render node the driver needs, so a machine without the hardware never reaches the stub dlopen. Linux still has no automatic platform default (`HwDevice::platform_default()` returns `None`) - VAAPI stays opt-in. Driver compatibility, fallback behavior and performance still need testing on real Intel/AMD Linux hardware before it is ever considered for a default.

4. **Per-timeline view-state is implemented and validated on main.** PR #88 merged as `56bde7c85e9fedc817092e2fdad59a3c19aeb09f`. It caches/restores zoom, horizontal and vertical scroll, playhead, selection, tool, snap and lane sizing per timeline. Switching/restoration/removal regression tests pass. Fresh exact-merge-commit CI passed all 3 jobs, Geneva both jobs, and Build app both Linux architectures (`43020200650`, `43020200640`, `43020200660`).

5. **The export queue is implemented on `main`.** PR #96 merged as `30a91b06b4bc6f0e90cfd8d5034a905acafe919f` (carrying PR #93's timeline-specific request building): a visible timeline picker, multiple queued jobs, per-job progress/stage/cancel/failure state, and tests proving each job exports the timeline it selected. Output read-back verification from PR #78 rides beside it.

6. **Motion-clip workflow: the command and the Motion page are merged; acceptance remains.** The validated `AddMotionClip` project command (comp/hash validation, automatic lane placement) and the Motion page - the project's comps listed and placed - landed on `main` through PR #97 (`ea589c73d7791572c75d5f1f12c557694d0cb269`, carrying PR #89's command work). Metadata editing, save/reopen round-trips, in-page preview and final-export acceptance tests remain.

7. **1080p proxy performance still needs target-hardware measurement.** Proxy scrubbing defaults on, and the proxy codec now defaults to MJPEG - every frame a keyframe, so random-frame decoding needs no reconstruction of neighbours - trading substantially larger files for that scrubbing responsiveness, with H.264 available in Settings as the small-file option. CI cannot establish smooth scrubbing on the user's antiX laptop. Verify proxy generation, proxy selection while scrubbing, original-frame restoration after pause, memory use, and sustained playback on the actual machine. Do not publish an 8–12x speedup claim without repeatable before/after measurements.

8. **The complete AI Director workflow needs end-to-end acceptance testing.** Unit tests and individual tools do not prove that a real project can reliably go from brief/script through footage selection, voice, motion, music, and final export without manual recovery. Track failures and verify a representative real project.

9. **The `v0.2.8-funcut.13` release is published but 127 commits behind current `main`.** The tag resolves to `ebfd9e30cf0e321236c4a73e231367289b3f41da`; `git rev-list --count v0.2.8-funcut.13..main` reports 127 commits ahead to current main `ed6a8b018be182a9c9cbb5a8aef80b1526212d59` (the PR #177 merge). The `.13` release has ten recorded assets, but it contains none of the later Director, planner, footage, proxy and motion work. No `.14` release is verified. Cutting `.14` owes: a clean security gate on the released commit (item 10 - green on `main` since #173 merged), the real AI Director acceptance run (item 11), and the target-hardware verification (item 12).

10. **The RustSec audit is clear on `main`: the `sherpa-onnx` 2.x migration landed as PR #173.** PR #173 moved `sherpa-onnx` from 1.13 to 2.0; `sherpa-onnx-sys` 2.0.2 builds against `zip 9`, so `zip 2.4.2` and the `zstd 0.13.3`/`zstd-safe 7.2.4` pair left the lockfile entirely. On `main` `cargo audit --file src/Cargo.lock` exits 0 with **zero** `--ignore` flags - the seven per-ID ignores and the two published advisories (`RUSTSEC-2026-0545`, `RUSTSEC-2026-0548`) are all gone by upgrade rather than suppression. The RustSec workflow job passed on #173 before the merge (2m38s) and again on `main` after it (run 44797335335, 2m45s), and the dependency-dance job passed after fetching the re-pinned v2.0.2 archives and verifying both digests against `scripts/ci/deps.lock`. `concat-speech` needed no source change and its 28 tests pass. A release cut from `main` can now claim a clean security gate.

11. **AUTO EDIT uses configured live-stock providers, but publishing provenance and end-to-end acceptance remain open.** PR #167 merged as `08c77063c361a8e91a0b83b0897ed8a211c8ecd4`: AUTO EDIT uses Pexels/Pixabay search/import, requires provider, ID, URL and licence metadata, and leaves a warned gap when no key is configured rather than falling back to OpenVid. PR #170 then merged as current main `e54e767562c7c0c963436be95149feb4d6a74e0f`, adding full-result-page hit selection, measured-duration refusal, per-take footage planning, explicit no-B-roll handling, and preview/revise before export. Those are on `main` now. What is still missing is durable per-clip author/caption/date provenance for publishing, applicable person/property releases and provider-terms review before any monetized release, and a real brief-to-final-export run on the intended laptop (see item 12). The watcher path now calls the sense door for its audio-repair readings and shops the licensed live shelves when a monetized brief refuses the OpenVid index (its 60+scenario self-test covers the fallback); the durable per-clip provenance for publishing remains open.

12. **The BGM library's FreePD shelf depends on archive.org, an environmental dependency outside this repository's control.** The FreePD catalog is fetched from `https://archive.org/metadata/freepd` and every FreePD track from `https://archive.org/download/freepd/<file>` (the constants in `src/crates/concat-host/src/bgm.rs`; `docs/BGM.md` names them). If the Internet Archive is slow, rate-limits, or reorganizes an item, `bgm_prepare` and `bgm_fetch` fail or stall through no fault of the code, and no mirror of those bytes ships in this repository or its releases (only the Lo-Fi catalog's ranged-read zip is pinned to a tagged GitHub release). The failure paths are recorded (`bgm_status` reports the shelf's state; the director treats an unready library as a warned, recorded absence, never a silent one) - but availability itself is environmental. P3-008: treat an archive.org outage as an environmental limitation, not a bug; a future hardening could mirror the FreePD catalog the way the sounds shelf is mirrored onto this repository's own `audio-v1` release.

## Previously reported issues now fixed on main

- **The RustSec audit is clear: the sherpa-onnx 2.x migration removed the last seven advisories.** The 2026-11-15 dependency session cleared thirteen by real upgrades (rustls 0.23.46, rustls-webpki 0.103.17, webpki-roots and webpki-root-certs 1.0.12, pulldown-cmark 0.13.6, libsqlite3-sys 0.39.1 through rusqlite 0.41.1, zip 9.6.0 for the dotLottie reader, tokio 1.54.1, rustix 1.1.6). The remaining seven (RUSTSEC-2026-0367/0368/0369/0429 on zip 2.4.2, 0391 on zstd 0.13.3, 0398/0403 on zstd-safe 7.2.4) all sat in the sherpa-onnx-sys 1.13.7 build-dependency subtree and were reviewed and ignored per-ID. sherpa-onnx-sys 2.0.2 builds against zip 9 instead, so that subtree carries no vulnerable zip and no zstd pair, and the seven `--ignore` entries are gone from the audit workflow: `cargo audit --file src/Cargo.lock` passes on `main` with no suppressions, including the two advisories (`RUSTSEC-2026-0545`, `RUSTSEC-2026-0548`) that the upgrade removed rather than ignored. `deps.lock`'s two sherpa rows are re-pinned to v2.0.2 with freshly computed sha256 digests, and `concat-speech` compiles unchanged against the 2.x API. Item 10 is resolved, and the audit runs green on `main` with no suppressions.
- **The reproduction's dead script references: the scripts are committed.** `scripts/setup-build-env.sh` and `scripts/funcut-env.sh` are now in the tree, repo-relative and parameterised: the first fetches the digest-pinned FFmpeg/ONNX/sherpa via `scripts/ci/fetch.sh` (with `--debs` for the no-root clang 19 runtime and headers under `sysroot/`), the second exports the CI engine job's env; `scripts/prune-dupes.sh` joins them for the disk-management note that also referenced a script that shipped nowhere. `TEST_EVIDENCE.md`, `AGENT_STATE.md` and `SESSION_HANDOFF.md` point at the repo-relative paths, and a clean-clone verification is recorded in TEST_EVIDENCE.md's reproduction section (fresh checkout, no root, `cargo check -p concat-media` green against the pinned FFmpeg).

- **Native Lottie and dotLottie playback: implemented.** PR #91: `NodeKind::Lottie` renders through rasterlottie with bounded v1/v2 dotLottie loading, image resolution and support diagnostics; CI/Geneva/Nix green on the merge.
- **VAAPI hardware encode: implemented (opt-in).** PR #95: the export sheet's GPU-by-name choice, `vaapi_first`, and the `vaapi_possible` render-node gate; CI green with the encoder lists never reaching a stub dlopen on hardwareless runners.
- **The export queue and timeline picker: implemented.** PR #96 (carrying PR #93): timeline picker, multiple jobs, per-job progress and cancel.
- **The MCP context cap: re-measured.** The export surface's growth (VAAPI choice, the queue's timeline picker) read 242,070 over 110 tools; the cap moved to 243,000 (`d13a4eec`), function, not prose.
- **Native `CompEngine`: implemented.** PR #79 merged the in-process tiny-skia compositor, including paths, shapes, text, still images, nested comps, masks, mattes, and supported effects. Lottie and shader packages remain outside its supported render set.
- **E303 timeline collision: fixed with regression coverage.** PR #78 handles sub-millisecond key collisions.
- **Export output verification: implemented.** PR #78 reads back the exported file and checks that it opens, contains video, and is close to the requested timeline duration.
- **Resolved on main: ONNX Runtime 1.28.0 archive HTTP 404.** PR #169 merged as `f13305fc1931e88d79bafd4112118fd0f9b8c19c`, replacing the unavailable 1.28.0 GitHub URLs with SHA-256-pinned ONNX Runtime 1.30.1 SourceForge mirror URLs for x64 and aarch64 and adding `scripts/ci/check-ort-pins.py`. Its PR-head CI [44364031838](https://github.com/coreselfmastery/FUNCUT/actions/runs/44364031838) passed all three jobs, Geneva [44364031575](https://github.com/coreselfmastery/FUNCUT/actions/runs/44364031575) passed both jobs, and Build app [44364031794](https://github.com/coreselfmastery/FUNCUT/actions/runs/44364031794) passed both architectures. The 1.28.0 failure is therefore fixed in the merged dependency pins. The connected integration did not return push-triggered runs or check contexts for merge SHA `f13305fc`, so exact-main validation remains separately unverified.

When a limitation is fixed, remove it from the remaining list only after the implementation and its regression evidence are present on `main`.
13. **The live timeline follow (PR #190) displays the run's document, one autosave behind the run.** The AUTO EDIT's live follow is a display of the sibling's `concat.json` re-read when its fingerprint changes, so the window shows the last landed edit, not the edit in flight; the run's engine session is the truth and the window reads the disk it autosaves. A follow on a machine whose server is off (a headless Director fallback) still works - nothing claims the folder then - but the landing's `release_window_session` warns and continues, which is correct and noisy. Scrubbing the live timeline plays proxy media, and a clip whose proxy has not been generated yet plays when the scheduler's proxy lane catches up; the first seconds of a fresh B-roll import can be filmstrip-only. None of these are silent: the read-only refusal is said, the follow's failure to begin is said, and the landing's failure to open is said.
