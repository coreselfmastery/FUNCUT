# Known issues and verified limitations

> Counts and the canonical feature inventory live in
> [docs/FEATURES.md](docs/FEATURES.md); this file carries the dated
> limitation detail, not the numbers. The second-pass audit of

This file records limitations that remain on `main`. It is not a list of historical bugs that have already been fixed.

## Remaining limitations

1. **Lottie/dotLottie playback is implemented on `main`.** PR #91 merged as `4a65a7b07b66d20d586d59c9da01cc05ab6624e9`: rasterlottie-backed `NodeKind::Lottie` playback, bounded v1/v2 dotLottie loading, image resolution and support diagnostics, with its full CI/Geneva/Nix matrix green on the exact merge head.

2. **Geneva sidecar is a pinned binary (v1.6.0, closed source).** Its limitations are documented in `docs/MOTION.md`: no path drawing, no variable-font axes, no in-keyframe weights, keyframes in px/% only, and markup animations static per bake. Keep the documented guards and warnings aligned with the actual sidecar behavior.

3. **Hardware decode is NVDEC by default on a data-centre NVIDIA part; VAAPI stays opt-in; on-hardware validation remains.** The export sheet names the machine's own GPU or the CPU by choice, and `vaapi_possible` gates every VAAPI encoder name on the DRI render node the driver needs, so a machine without the hardware never reaches the stub dlopen. `HwDevice::platform_default()` now reads the model from `/proc/driver/nvidia/gpus` and takes NVIDIA's NVDEC on a `Tesla`-line part (T4, V100, A100, H100, L4, L40 and the rest), without loading libcuda to answer; VAAPI stays opt-in because of issue #70, and a desktop or hybrid laptop's NVIDIA card stays on the CPU because of #309. `CONCAT_HARDWARE_DECODE=auto|cuda|vaapi|off` overrides it. The export sheet's GPU row is now offered wherever VAAPI or NVENC is reachable, and choosing it leads with every hardware family, not only VAAPI. Driver compatibility, fallback behavior and performance still need testing on real Intel/AMD/NVIDIA Linux hardware, a T4 included, before any of it is called validated.

4. **Per-timeline view-state is implemented and validated on main.** PR #88 merged as `56bde7c85e9fedc817092e2fdad59a3c19aeb09f`. It caches/restores zoom, horizontal and vertical scroll, playhead, selection, tool, snap and lane sizing per timeline. Switching/restoration/removal regression tests pass. Fresh exact-merge-commit CI passed all 3 jobs, Geneva both jobs, and Build app both Linux architectures (`43020200650`, `43020200640`, `43020200660`).

5. **The export queue is implemented on `main`.** PR #96 merged as `30a91b06b4bc6f0e90cfd8d5034a905acafe919f` (carrying PR #93's timeline-specific request building): a visible timeline picker, multiple queued jobs, per-job progress/stage/cancel/failure state, and tests proving each job exports the timeline it selected. Output read-back verification from PR #78 rides beside it.

6. **Motion-clip workflow: the command and the Motion page are merged; acceptance remains.** The validated `AddMotionClip` project command (comp/hash validation, automatic lane placement) and the Motion page - the project's comps listed and placed - landed on `main` through PR #97 (`ea589c73d7791572c75d5f1f12c557694d0cb269`, carrying PR #89's command work). Metadata editing, save/reopen round-trips, in-page preview and final-export acceptance tests remain.

7. **1080p proxy performance still needs target-hardware measurement.** Proxy scrubbing defaults on, and the proxy codec now defaults to MJPEG - every frame a keyframe, so random-frame decoding needs no reconstruction of neighbours - trading substantially larger files for that scrubbing responsiveness, with H.264 available in Settings as the small-file option. CI now runs a short `preview.frame` and render under a 4 GiB address-space cap (`scripts/benchmark.py --memory-limit-mb 4096`), so a memory regression fails before a release. It still cannot establish smooth scrubbing on the user's antiX laptop: verify proxy generation, proxy selection while scrubbing, original-frame restoration after pause, memory use, and sustained playback on the actual machine. Do not publish an 8–12x speedup claim without repeatable before/after measurements.

8. **The complete AI Director workflow needs end-to-end acceptance testing.** Unit tests and individual tools do not prove that a real project can reliably go from brief/script through footage selection, voice, motion, music, and final export without manual recovery. The run now records per-stage wall times in `auto-edit-receipt.json` (`elapsedMs`), so a slow stage can be named, but that is instrumentation, not acceptance. Track failures and verify a representative real project.

9. **The `v0.2.8-funcut.15` release is published and its release workflow is fully green after a rerun.** `.15` is the latest release, with ten assets, matching checksums and a verified manifest. The `.14` run was cancelled and superseded. The first `.15` run [45163610747](https://github.com/coreselfmastery/FUNCUT/actions/runs/45163610747) passed the tag check, CI, the RustSec audit and both Linux build jobs, then lost its Nix runner to GitHub's "hosted runner lost communication" annotation after about 1.5 hours. The rerun passed the Nix build and the publish job, and every job in the run is now success. The release body was restored to the letter plus the `.14.. .15` commit list after the publish job regenerated it. Target-machine proxy/Geneva acceptance and a real AI Director project run remain owed.

10. **`RUSTSEC-2026-0592` is fixed on `main`; the audit warnings are triaged, not suppressed.** PR #202 merged the `url 2.5.9` upgrade and the compatible `form_urlencoded 1.2.3` lock. The RustSec audit passes with no `--ignore` suppressions; the remaining advisories are unmaintained-crate and yanked-version warnings, recorded in the audit job rather than hidden. The `.13` tag still ships `url 2.5.8`; `.14` and `.15` carry the fixed lock.

11. **AUTO EDIT now has a stronger creative contract, but publishing provenance and real-project acceptance remain open.** PR #167 and #170 added licensed live-stock search/import, measured-duration refusal, per-take footage planning, explicit no-B-roll handling, and preview/revise before export. PR #200 merged as `fa68c059945e0eef9151d0fd2010134f41620c05`, adding style and retention requirements, a 25-phase Director skill, signal-to-decision recipes, and an independent acceptance gate for the timeline-ready default (export remains explicit). PR #200's head passed all seven CI/Geneva/Build-app check-runs, but it had no formal review submissions; no real brief-to-export run on the target machine is recorded. Durable per-clip author/caption/date provenance, applicable person/property releases, provider-terms review before monetized publishing, and E4 product acceptance remain open. The watcher self-test covers mocked safety scenarios; that is not a real project run.

12. **The BGM library's FreePD shelf depends on archive.org, an environmental dependency outside this repository's control.** The FreePD catalog is fetched from `https://archive.org/metadata/freepd` and every FreePD track from `https://archive.org/download/freepd/<file>` (the constants in `src/crates/concat-host/src/bgm.rs`; `docs/BGM.md` names them). If the Internet Archive is slow, rate-limits, or reorganizes an item, `bgm_prepare` and `bgm_fetch` fail or stall through no fault of the code, and no mirror of those bytes ships in this repository or its releases (only the Lo-Fi catalog's ranged-read zip is pinned to a tagged GitHub release). The failure paths are recorded (`bgm_status` reports the shelf's state; the director treats an unready library as a warned, recorded absence, never a silent one) - but availability itself is environmental. P3-008: treat an archive.org outage as an environmental limitation, not a bug; a future hardening could mirror the FreePD catalog the way the sounds shelf is mirrored onto this repository's own `audio-v1` release.

13. **AUTO EDIT live timeline follow is a last-landed snapshot, not an in-flight preview.** PR #190's follow re-reads the sibling project's `concat.json` when its autosave fingerprint changes, so the window shows the last landed edit and can be one autosave behind the Director run. A headless fallback still proceeds when the local server is off; the landing warns if the window session cannot be opened. The live timeline uses proxy media; a fresh B-roll clip may initially show only its filmstrip until its proxy is generated. The refusal and fallback paths are logged rather than silently hidden.

14. **Main is protected and exposes three required checks; the remaining protection rules are not independently verified in this run.** The branch endpoint reports `protected=true` and required contexts `Format, locales and models`, `The analysis senses against real fixtures` and `Engine tests and lints`, with enforcement level `everyone`. The detailed branch-protection endpoint returned 403 to the connected GitHub integration, so PR-only changes, required approval count, admin enforcement, conversation-resolution, force-push and deletion settings cannot be independently confirmed here.

15. **The full-intelligence integration is merged; current AUTO EDIT door consumption is 67/76, not complete.** The original source work (#214, #217, #218) landed through #220, and subsequent merged work includes #222, #225–#227, #229–#237 and #239–#242 (PR #224 closed without merging; #228 and #238 remain open). Keep the implementation and the remaining gaps distinct:
    - **The picture set and measured SFX placement are now headless.** PR #222 merged as `02297cd7782f8fdfa1a18b65dc6954ff978c536c`: `models_download {kind: "picture", id: "picture-models"}` is supported by the API, and the placement check can correct or drop a sound accent rather than trusting the shelf's `syncAt`. The current API accepts `tts`, `whisper`, `sound` and `picture` download kinds.
    - **The headless runner now fans independent take work and preflights Whisper.** `auto_edit.rs` opens `LaneOpener` lanes and calls `run_with_lanes_and_cancellation`; `director_program.rs` fans AudioRepair, Transcribe and VoiceSignals work and runs a Whisper-base download/wait gate before the handoff. The default AUTO EDIT still leaves export explicit: it creates an editable timeline and preview/revise evidence rather than silently rendering a final file.
    - **Current door-consumption measurement (main `50171fb6`, CI job [140093862274](https://github.com/coreselfmastery/FUNCUT/actions/runs/45873277319/job/140093862274)):** 76 door readings exist; AUTO EDIT asks for 67 (88%); all 76 are named in `signal_matrix.md`. The asked counts are visual_sense 34/34, voice_quality 6/6, prosody_style 6/6 and discourse 10/10. The nine unasked actions are `sound_sense.describe_sound`, `sound_sense.rank_sounds`, `sound_model.plan`, `captions.evaluate_tts_quality`, `captions.seal_voice`, `audio_repair.analyze_music_structure`, `audio_repair.identify_music`, `audio_repair.normalize_loudness` and `audio_repair.remove_hiss_hum_rumble`.
    - **The coverage ledger is informational, not a release gate.** `scripts/check-signal-coverage.py` prints 67/76 and explicitly says `--require-button` is not enabled. The separate 71-entry voice-profile catalogue is checked for matrix/alias consistency, but this door ledger does not prove that every one of those 71 profile readings changes a timeline decision. Do not claim all 147 readings are consumed.
    - **Model availability is not a strict all-model preflight.** Whisper base is downloaded and waited on before the run. The picture set and sound generator sets can be downloaded headlessly, and `sense_visual {action: "models"}` probes installed picture doors, but AUTO EDIT does not currently block startup until every selected picture/sound set is present. A missing optional set can leave the run on classical/stock fallbacks. If the operating rule is “download every selected model before starting,” that remains an integration requirement.
    - **The model mirror is filled, but its latest run is on an earlier branch.** Mirror Models run [45644419485](https://github.com/coreselfmastery/FUNCUT/actions/runs/45644419485) passed on `284fb0f0`; current-main CI checks the 51-model / 5.06 GB manifest, but that manual mirror run is not on current main. 26 of the 30 visual shelf entries remain operator-sourced; four are digest-verified, and the rest are pinned on first download.
    - **Publishing provenance is improved but not complete.** PR #227 persists provider, provider id, source URL, licence and author on each stock-imported media item and in the run receipt. It does not yet provide a durable import timestamp/caption, applicable person/property releases or a provider-terms review for monetized publishing.
    - **What remains:** wire the nine unasked door actions where they are relevant, add an enforced consumption gate only when the required coverage is genuinely complete, enforce the selected-model preflight policy, and complete E4 acceptance - a real brief/script + narration + footage + motion + sound + editable timeline + inspected export on the actual antiX machine. Target-machine 1080p long-GOP measurements remain separate from hosted render benchmarks.

## Previously reported issues now fixed on main

- **The previously reported zip/zstd vulnerability advisories were removed by the sherpa-onnx 2.x migration.** The 2026-11-15 dependency session cleared thirteen by real upgrades (rustls 0.23.46, rustls-webpki 0.103.17, webpki-roots and webpki-root-certs 1.0.12, pulldown-cmark 0.13.6, libsqlite3-sys 0.39.1 through rusqlite 0.41.1, zip 9.6.0 for the dotLottie reader, tokio 1.54.1, rustix 1.1.6). The remaining seven advisories in the sherpa-onnx-sys 1.13.7 subtree disappeared when the project moved to 2.0.2; the seven `--ignore` entries were removed rather than retained. The latest audit on `c8505e021f72824bfe5f6a08dda141522b2db690` exits 0 with no suppressions, but still reports the 11 allowed unmaintained/yanked warnings listed in item 10. PR #202's updated head `53213b2dcec42ab323ef6f87ea14fab4aac36c71` upgrades `url` to `2.5.9` and `form_urlencoded` to `1.2.3`; its RustSec gate passes with 11 allowed unmaintained/yanked warnings still needing triage. The earlier zip/zstd advisories are resolved, but dependency security is not yet clean.
- **The reproduction's dead script references: the scripts are committed.** `scripts/setup-build-env.sh` and `scripts/funcut-env.sh` are now in the tree, repo-relative and parameterised: the first fetches the digest-pinned FFmpeg/ONNX/sherpa via `scripts/ci/fetch.sh` (with `--debs` for the no-root clang 19 runtime and headers under `sysroot/`), the second exports the CI engine job's env; `scripts/prune-dupes.sh` joins them for the disk-management note that also referenced a script that shipped nowhere. `TEST_EVIDENCE.md`, `AGENT_STATE.md` and `SESSION_HANDOFF.md` point at the repo-relative paths, and a clean-clone verification is recorded in TEST_EVIDENCE.md's reproduction section (fresh checkout, no root, `cargo check -p concat-media` green against the pinned FFmpeg).

- **Native Lottie and dotLottie playback: implemented.** PR #91: `NodeKind::Lottie` renders through rasterlottie with bounded v1/v2 dotLottie loading, image resolution and support diagnostics; CI/Geneva/Nix green on the merge.
- **VAAPI hardware encode: implemented (opt-in).** PR #95: the export sheet's GPU-by-name choice, `vaapi_first`, and the `vaapi_possible` render-node gate; CI green with the encoder lists never reaching a stub dlopen on hardwareless runners.
- **The export queue and timeline picker: implemented.** PR #96 (carrying PR #93): timeline picker, multiple jobs, per-job progress and cancel.
- **The MCP context cap: re-measured.** The export surface's growth (VAAPI choice, the queue's timeline picker) read 242,070 over 110 tools; the cap moved to 243,000 (`d13a4eec`), function, not prose.
- **Native `CompEngine`: implemented.** PR #79 merged the in-process tiny-skia compositor, including paths, shapes, text, still images, nested comps, masks, mattes, and supported effects. Lottie and shader packages remain outside its supported render set.
- **E303 timeline collision: fixed with regression coverage.** PR #78 handles sub-millisecond key collisions.
- **Export output verification: implemented.** PR #78 reads back the exported file and checks that it opens, contains video, and is close to the requested timeline duration.
- **Resolved on main: ONNX Runtime 1.28.0 archive HTTP 404.** PR #169 merged as `f13305fc1931e88d79bafd4112118fd0f9b8c19c`, replacing the unavailable 1.28.0 GitHub URLs with SHA-256-pinned ONNX Runtime 1.30.1 SourceForge mirror URLs for x64 and aarch64 and adding `scripts/ci/check-ort-pins.py`. Its PR-head CI [44364031838](https://github.com/coreselfmastery/FUNCUT/actions/runs/44364031838) passed all three jobs, Geneva [44364031575](https://github.com/coreselfmastery/FUNCUT/actions/runs/44364031575) passed both jobs, and Build app [44364031794](https://github.com/coreselfmastery/FUNCUT/actions/runs/44364031794) passed both architectures. The 1.28.0 failure is therefore fixed in the merged dependency pins. The connected integration did not return push-triggered runs or check contexts for merge SHA `f13305fc`, so exact-main validation remains separately unverified.
