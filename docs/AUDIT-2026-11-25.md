## 2. What the audit found on main, and what this change fixes

The headline gap: **`sense_sound` and `sense_sound_model` were registered
and on the Director's own allowlist, but the Director skill never
mentioned them** — the skill still taught guessed attack lead-ins and
manifest `syncAt`, the very practice the shelf audit measured wrong 30% of
the time. A tool the skill does not teach is a tool the Director does not
call.

## 3. The open PRs — what each needs before merge

**#214 (auto_edit sibling-path fix)** — SAFE TO MERGE. One file
(`auto_edit.rs`), no collisions with main, four targeted tests
(`.`-spelled source containment, `..`-media escape, stale-evidence
non-carry-over, surfaced write failures). Recommend landing first.

**#217 (visual sense picture reader)** — DO NOT MERGE AS-IS. It branches
from pre-#216 main and carries the pre-fix `sound_model.py` selftest
(hard-fails without numpy), so merging regresses #216. Beyond the rebase:

- The registry claims 30 ONNX rows; only 5 specialised handlers exist
  and 26 rows share one generic preprocess/decode pipeline; the 4 VLM
  rows (`smolvlm2-500m`, `florence-2-base`, `uform-gen2`,
  `smolvlm2-256m`) have no ONNX implementation at all — the door refuses
  them by design and the selftest asserts the refusal. A registry row
  whose model cannot run is a claim, not a capability.
- Only 4 of the 30 rows carry a fetchable `hfRepo`/`hfFile`; the other
  26 rows' `upstream` fields are pages, and the PR's own `download`
  refuses to invent links — so 26/30 rows cannot be installed by the
  PR's own flow.
- `movenet-a0` is registered as the action-class door; MoveNet is a pose
  model (a correct `movenet-pose` row also exists).
- The registry sits OUTSIDE `models/manifest.toml` and the Rust
  `ModelId` table: no sha256-before-keep (trust-on-first-use pins
  whatever arrived), no mirror row, no settings-sheet integration — in
  tension with the manifest's own "a download with no digest is
  refused" policy.
- The right order: rebase onto current main, move the rows into the
  manifest with digests, fix the mislabel, then wire the
  enrichment doors (`measure_clips` silently omits non-ready doors
  today) and re-measure the schema caps.

**#218 (sound generation)** — DO NOT MERGE AS-IS. Same pre-#216 base
(numpy selftest regression), plus heavy textual collisions with #217
(`sound_model.py`, `sense.rs` member counts 44 vs 81, `schema.rs` caps,
`tool_reference.md`). Beyond the rebase:

- `docs/SOUND-GENERATION.md` claims "`models_list` / `models_download`
  do the same headless", but `concat-api/src/speech.rs` still rejects
  every model kind except `tts`/`whisper` — the headless path for the
  three generator sets is unimplemented; the Python refusal text points
  at a door that refuses.
- The doc's on-disk sizes overstate the manifest sums by ~1.5–2.3×
  (0.48/1.2/1.0 GB claimed vs 0.36/0.54/0.45 GB pinned).
- TinyMusician's licence is unresolved upstream — generated music must
  not ship in monetized work until it is.
- No Python selftest covers `generate` (the selftest is still the
  reader's 19 checks).
